**Completeness Rules (applies to all records):**
1.  **Required Fields (Rollover):** If the record is for a Rollover, the `input` object MUST contain `section`, `consideration`, and `asset_profile`. The `output` object MUST contain `eligibility` and `tax_comparison`.
2.  **Required Fields (B-BBEE):** If the record is for a B-BBEE Scorecard, the `input` object MUST contain `shareholders`, and the `output` object MUST contain `indicators` and `total_ownership_points`.
3.  **Required Fields (Residency):** If the record is for a Residency Plan, the `input` object MUST contain `ordinary_residence_flags` and `days_in_current_year`. The `output` MUST contain `status` and `reasoning`.

**Rollover Planner Rules (applies if meta.source_prompt_id contains 'ROLL'):**
1.  **S42 Eligibility:** If `input.section` is 's42', the `output.eligibility.eligible` field must be consistent with the core requirements (e.g., `input.consideration.shares_issued` must be true for the transaction to be eligible).

3.  **Tax Calculation:** The `output.tax_comparison.cgt_no_relief` must be arithmetically plausible based on the `input.asset_profile.market_value` and `input.asset_profile.base_cost`.
4.  **Deferral Logic:** If `output.eligibility.eligible` is true and there is a capital gain, `output.tax_comparison.net_deferral_benefit` must be greater than 0.

**B-BBEE Scorecard Rules (applies if meta.source_prompt_id contains 'BBBEE'):**
1.  **Points Summation:** The `output.total_ownership_points` must be the sum of all points in the `output.indicators` object.
2.  **Sub-minimum Met:** The `output.indicators.net_value.sub_minimum_met` flag must be consistent with the points awarded for that indicator.

**Residency Planner Rules (applies if meta.source_prompt_id contains 'RES'):**
1.  **Ordinary Residence:** If `input.ordinary_residence_flags.has_permanent_home` is true, the `output.status` should likely be "Resident".
2.  **Physical Presence Test:** If the individual is not ordinarily resident, the `output.status` must be consistent with the day-counting rules of the physical presence test (e.g., >91 days in current year, >91 days in each of the last 5 years, >915 days total).

Return exactly one JSON object with keys:
{"pass": true|false, "failed_reasons": ["string", ...], "explanation": "string (1-3 sentences)"}
